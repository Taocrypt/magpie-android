手机就是你的网关

magpie 管模型和账号，外壳管它在手机上跑得稳、用得顺手。

常驻网关

前台服务运行官方 magpie CLI，可开机自启。顶栏状态胶囊、通知栏和快捷磁贴都能启停或重启。

悬浮窗

透明度、尺寸、悬浮球都可调，支持贴边、自动隐藏和点击穿透。点图标即以悬浮球打开。

远程访问

Cloudflare 临时隧道、Tailscale、局域网和 mDNS。组件第一次开启时才下载，更新要你确认。

应用内更新

内核和外壳分开检查，启动时提示新版本和更新日志。可选镜像，校验签名后再安装，内核支持回滚。

网络兼容

本地 DNS 代理固定端口，可再串 http 或 socks5 上游代理，magpie 和外壳的下载都走它。

空间管理

按大小列出缓存、日志和组件占用，单独清理或一键清理。内置 Bun，插件开箱即用。

移动端适配

向网页面板注入移动端样式；网页的 alert、confirm、prompt 统一成底部弹窗，支持上传下载文件，渲染崩溃自动恢复。

日志与诊断

查看网关日志，导出崩溃日志和诊断信息；更新下载与安装进度显示在通知栏。

工作原理

外壳以子进程运行官方 magpie CLI，用 WebView 打开它自带的网页面板。

┌──────────────────── Android 手机 ────────────────────┐
│  magpie (com.magpie.android)                          │
│   ├─ 前台服务 ── 进程守护 / DNS 代理 / 隧道            │

官方内核

首次启动从 usemagpie.ai 下载 magpie-cli-android-arm64，失败改走 GitHub，校验 SHA-256。APK 只内置插件用的 Bun。

默认只在本机

网关 3425、面板 3430，可改；DNS 代理固定 3435。开启局域网或远程访问后才对外可达。

为什么 targetSdk 28

Android 只允许 targetSdk ≤ 28 的应用执行自己下载的二进制，这是不打包 CLI 也能运行的前提。

三步装好

1

下载 APK

从 Releases 下载 magpie-<版本>.apk，允许浏览器安装未知应用。

2

首次启动

外壳会从官方渠道下载 magpie CLI 并校验 SHA-256，完成后网关自动启动。

3

把 Agent 指向它

复制顶栏地址，例如 http://127.0.0.1:3425/v1，在网页面板里配好模型和账号。

常见问题

为什么首次启动要下载东西？

magpie CLI 直接来自上游官方渠道并校验 SHA-256，APK 只保留外壳，体积小，上游更新也不必等外壳发版。网络不畅时可在「检查更新 → 下载设置」里配置镜像。

后台被杀、熄屏后网关不通？

在「应用设置」里开启「忽略电池优化」；部分国产系统还需允许「自启动」「后台运行」，并在多任务界面锁定应用。

怎么让电脑或外网用上手机的网关？

同一 Wi-Fi 下打开「允许局域网访问」，用手机 IP 加端口访问；不在同一网络时，在「远程访问」里启用 Cloudflare 临时隧道或 Tailscale。请只在可信网络中使用，并设置好网关密钥。

内核更新后出了问题？

在「检查更新」的内核卡片里可以回滚到上一版本。

能自己编译吗？

可以，项目不依赖 Gradle，build.sh 直接调用 Android SDK 工具链。自己签名的包与官方包签名不同，不能覆盖安装，外壳自更新也会拒绝安装。步骤见 README。

这是官方客户端吗？

不是。这是社区作品，与 magpie 作者无关。magpie 本身的问题请到 yetone/magpie 反馈。
